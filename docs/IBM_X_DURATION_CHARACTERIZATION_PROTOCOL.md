# Frozen native X-duration characterization (free QPU)

Prepared before the new QPU job and before inspecting any outcomes. The goal is to test whether `ibm_marrakesh` offers an empirically useful choice between two physical implementations of the **same** logical X gate. This is a prerequisite for, not a demonstration of, GP scheduling benefit.

- Use only the existing IBM Open instance and physical qubits 0 and 1. Backend target reports native `x` at 36 ns and `xslow` at 1,000 ns on both qubits. The backend lists the same error for both, which is not independent evidence of equal gate error.
- For each qubit and measurement basis Z or X, prepare the corresponding `|0>` or `|+>` state, apply an even number `m` of X operations, invert the preparation for X-basis readout, and measure the probability of returning `0`. Use `m` in {0, 8, 32, 64}; 3 randomized blocks; 1,024 shots per circuit. `m=0` is a shared preparation/readout control.
- At each nonzero `m`, compare three policies: `fast` uses native `x`; `padded` uses `x` followed by a 964-ns delay; `slow` uses native `xslow`. The latter two have the same nominal total sequence duration. The same ideal unitary, qubit, measurement basis, block, and shot count are used across policies. No twirling, dynamical decoupling, or error mitigation.
- Compile with optimization level 0, fixed physical layout, and verify that `xslow` and delays survive. Save pre-job target properties, QPY, QASM, randomized order, counts, status, and job ID. The QPU job has a 90-second execution cap.
- Primary descriptive comparison: X-basis return at `m=32`, averaged over the three blocks for each qubit. Report `slow-fast` and `slow-padded` differences with shot-only uncertainty, plus every other basis and length. A positive `slow-padded` difference would indicate a possible control-shape benefit at matched duration; it is not by itself a GP improvement. Do not select a winning qubit, length, or basis after seeing data and call it the primary result.
- A useful discrete duration tradeoff exists only if at least one slower implementation has a reproducible lower measured error after accounting for matched duration and uncertainty. A later, independently held-out circuit test must compare an optimizer using training data with the fastest-gate baseline and established scheduling controls. If `xslow` is dominated, report that limitation and do not claim physical improvement.
