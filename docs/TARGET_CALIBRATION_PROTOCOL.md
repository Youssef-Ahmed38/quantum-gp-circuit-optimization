# Target-device calibration required for a physical claim

The saved `ibm_torino` properties contain one nominal error and duration per native gate. They do not identify an error-versus-duration law or establish that a user can deploy alternate-duration pulses. This protocol specifies the missing experiment; it is **not** a record of a GP hardware comparison. The repository now also contains two free Heron QPU jobs: an access control and a separate idle-noise pilot. Neither varies native gate duration or executes the GP policy; see [HARDWARE_STATUS.md](HARDWARE_STATUS.md).

1. On an accessible target device, identify one native gate family and physical qubit or edge for which multiple pulse implementations produce the same intended unitary. Record the pulse waveform or immutable hash, pulse shape, gate duration, calibration time, backend identifier, physical qubits, and applicable controller timing constraints for each implementation. Do not pool qubits, pulse families, or calibration epochs as if they were one duration sweep.
2. Characterize each implementation with repeated randomized benchmarking or an appropriate gate-characterization protocol. Preserve raw counts or survival data, sequence lengths, randomization seeds, fit method, error-per-gate estimate, and its uncertainty. Repeat measurements across calibration epochs to quantify drift; capture contemporaneous idle and coherence measurements. Use interleaved reference data where the characterization method requires it.
3. Split observations before fitting. Fit model coefficients and choose any model family using training epochs and durations only. Reserve other durations, later epochs, and circuits for evaluation. If model selection has already used the present public sweep, treat that sweep as development data; do not call it a prospective test.
4. Evaluate prediction error relative to both reported measurement uncertainty and observed model discrepancy. Where the assumed law fails, reject its physical prediction or use a conservatively characterized finite pulse library. A band or bound must state its construction and empirical coverage; a source error bar alone is not a prediction interval.
5. Give GP, ASAP, ALAP, DD, and a characterized discrete scheduler the **same actual pulse library**, qubit mapping, logical circuit, calibration epoch, and wall-clock deadline. Record compilation and pulse-selection time separately from execution time. Run randomized order and sufficient repeats to estimate uncertainty and drift. Report every failure and regression alongside circuit fidelity, makespan, gate count, and idle time.

The existing local benchmark in `evidence/direct_matched/` already checks circuit and deadline matching, but its GP options are hypothetical continuous durations. The published single-qubit sweep in `evidence/measured_duration/` provides real duration options from a different platform, without matched circuit-level GP-versus-scheduler hardware outcomes. Neither dataset can substitute for the target-device experiment above.
